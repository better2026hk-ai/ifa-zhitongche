# IFA直通车 小程序 · 技术交接文档

> 本文档面向负责实际开发的一方（人或 AI，例如 Claude Code）。所有设计决策、数据结构、交互逻辑均以本文档 + 附带的 HTML 设计原型（`IFA直通车_小程序整合原型.html`）为准。原型文件里的所有交互都是**真实可点击、真实计算**的（不是静态图），可以直接在浏览器里打开体验，作为最终验收标准。

## 0. 项目背景

**产品名称**：IFA直通车
**定位**：香港保险中介人资格考试（IIQE）备考小程序，覆盖：
- Paper Ⅰ 保险原理及实务
- Paper Ⅱ 一般保险
- Paper Ⅲ 长期保险
- Paper Ⅴ 投资相连长期保险
- MPF 强制性公积金计划考试

**核心功能**：题库练习（即时反馈）、模拟考试（限时限量、交卷出分）、错题本（自动收录、可重新组卷测验）、个人学习数据统计。

## 1. 推荐技术方案

| 层面 | 建议 | 原因 |
|---|---|---|
| 前端框架 | **Taro**（React 语法编译到小程序）或原生 WXML/WXSS | Taro 上手快、生态好；如果开发者更熟悉原生小程序语法也可以直接用 WXML |
| 后端 | **微信云开发（CloudBase）** | 免服务器运维，自带数据库、云函数、文件存储，最适合非专业运维团队 |
| 数据库 | 云开发自带的 NoSQL 数据库 | 题库、用户数据、错题记录、模考历史都可以用集合（collection）存储 |
| 登录 | `wx.login()` + 云开发用户体系 | 真机上可以拿到 openid，配合云开发的用户管理，免去自建鉴权 |
| 头像/昵称 | `<button open-type="chooseAvatar">` + `<input type="nickname">` | 微信 2022 年后强制要求的合规写法，详见第 5.1 节 |

## 2. 页面结构与导航地图

App 分为「未登录」和「已登录」两大状态，已登录后是标准的 4 个 Tab。

```
[启动]
  └─ 未登录 → 登录页（微信授权登录按钮）
       ├─ 点击「用户协议」/「隐私政策」→ 协议查看页（返回登录页）
       └─ 点击登录 → 微信授权确认弹窗 → 允许 → 完善资料页（选头像+填昵称）→ 完成 → 首页

[已登录，底部 4 个 Tab]
  ├─ 首页
  │    ├─ 题库选择器（点击弹出底部选择面板，5 个科目）
  │    ├─ 仪表盘（进度环 + 掌握度 + 继续练习按钮）
  │    ├─ 我的题库列表（5 张卡片，点击切换仪表盘显示的科目）
  │    └─ 点击「继续练习」或题库卡片 → 进入练习模式（全屏，隐藏 TabBar）
  │
  ├─ 模拟考试
  │    ├─ 列表页（5 张科目卡片，含真实考试规则：时长/题数/合格线）
  │    └─ 点击科目 → 规则页 → 开始 → 答题页 → 交卷确认 → 出分页 → 逐题复盘
  │         （进入考试后全屏，隐藏 TabBar，直到交卷才恢复）
  │
  ├─ 错题本
  │    ├─ 列表页（按科目分组，只显示「科目名 + 错题数」）
  │    └─ 点进某科目 → 该科目错题详情（可展开查看解析）
  │         └─ 「组一次错题测验」→ 勾选题目 → 测验（即时反馈，答对自动从错题本移除）
  │
  └─ 我的
       ├─ 个人信息（头像/昵称，点击编辑图标可修改）
       ├─ 学习总览（6 个统计卡片，全部来自真实答题记录，见第 4.3 节）
       ├─ 模拟考试记录（预览最近 3 次，超过 3 次可展开查看最近 20 次）
       ├─ 账号管理（微信昵称/账号ID/注册时间/绑定手机）
       ├─ 意见反馈（5 星评分 + 100 字建议 + 提交）
       └─ 关于我们 / 退出登录
```

**练习模式和模拟考试进入后都会隐藏底部 TabBar**，防止答题过程中误触跳出，退出/交卷后才恢复。

## 3. 数据结构设计

### 3.1 题库数据（5 个 JSON 文件，见 `question-banks/` 文件夹）

每道题的结构固定为：

```json
{
  "chapter": "一",
  "chapter_title": "風險與保險基礎",
  "stem": "113. 心臟問題屬於那一種風險?",
  "options": { "A": "普通風險", "B": "投機風險", "C": "特定風險", "D": "基本風險" },
  "answer": "C",
  "explanation": "特定風險是指影響範圍有限的風險"
}
```

字段说明：
- `chapter`：中文数字（一/二/三/…），代表章节序号
- `chapter_title`：章节名称（部分科目原始资料未标明具体主题，只有「第一章」这种编号，是正常情况，不是缺失）
- `stem`：题干，**开头已经拼好了章节内序号**（如 "113. "），这是刻意设计——练习模式里按此顺序显示；但在**模拟考试和错题测验里，这个序号会在展示前被程序去掉**（因为模拟考试是跨章节随机抽题，原来的编号没有意义），去除方法：用正则 `^\d+\.\s*` 替换成空
- `options`：固定 4 个选项 A/B/C/D
- `answer`：正确答案字母
- `explanation`：解析文字，**部分题目（卷一、卷三旧版）没有这个字段/为空字符串**，界面要做好「没有解析就不显示解析模块」的判断，不能假设一定有

各题库题量：
| 科目 | 文件名 | 题量 |
|---|---|---|
| Paper Ⅰ | paper1_保险原理及实务.json | 913 |
| Paper Ⅱ | paper2_一般保险.json | 655 |
| Paper Ⅲ | paper3_长期保险.json | 930 |
| Paper Ⅴ | paper5_投资相连长期保险.json | 649 |
| MPF | mpf_强制性公积金计划.json | 601 |

### 3.2 真实考试规则（写死在代码里的常量，不需要存数据库）

| 科目 key | 名称 | 时长 | 抽题数 | 合格题数(70%) |
|---|---|---|---|---|
| p1 | Paper Ⅰ · 保险原理及实务 | 120分钟 | 75题 | 53题 |
| p2 | Paper Ⅱ · 一般保险 | 75分钟 | 50题 | 35题 |
| p3 | Paper Ⅲ · 长期保险 | 75分钟 | 50题 | 35题 |
| p5 | Paper Ⅴ · 投资相连长期保险 | 120分钟 | 80题 | 56题 |
| mpf | MPF · 强制性公积金计划 | 120分钟 | 80题 | 56题 |

模拟考试**每次开考都从对应题库里随机抽取指定数量的题目**（不是固定的一套题），这样每次模考体验都不完全一样。

### 3.3 用户数据（需要数据库持久化，原型里是内存变量，刷新即丢失）

```
users 集合（每个微信用户一条）：
  - openid（微信身份标识）
  - nickname（昵称）
  - avatarUrl（头像，如果用 chooseAvatar 会拿到临时/云存储链接）
  - createdAt（注册时间，即首次登录时间）

paperStats 子集合（每用户每科目一条，用于「学习总览」统计）：
  - userId
  - paperKey（p1/p2/p3/p5/mpf）
  - done（已作答题数，累加）
  - correct（答对题数，累加）

activityDates（记录哪些日期有过答题行为，用于算「连续打卡天数」）：
  - userId
  - date（YYYY-MM-DD）

examHistory 集合（每次模拟考试交卷生成一条）：
  - userId
  - paperKey
  - questions（本次抽到的题目快照，含用户当时的作答 answers）
  - total / correct / passed
  - timestamp

wrongBook 集合（每道错题一条，按 userId + paperKey + stem 去重）：
  - userId, paperKey, paperTag, paperName
  - stem, options, answer, lastPicked, explanation
  - wrongAt（最近一次答错的时间）
```

**关键逻辑：任何时候只要某道题被答对，且它当前存在于该用户的错题本里，就要把它删除**——这条规则在练习模式、模拟考试、错题本自己的测验里都要生效，不区分来源（详见第 5.4 节）。

## 4. 核心功能逻辑说明

### 4.1 首页仪表盘

- 顶部题库选择器 + 进度环，**显示的百分比 = 当前科目已练习题数 / 该科目题库总题量**
- "已练习题数"、"正确率"来自 `paperStats`，不是静态数字
- 描述文案是动态生成的：
  - 没开始练习：「还没有开始练习，现在就开始吧！」
  - 有进度：「按当前进度（约每天 30 题），预计还需 X 天完成全部题库一轮练习。」（X = 剩余题数 ÷ 30，向上取整）
  - 已完成一轮：「恭喜，已完成 XX 题库的一轮练习！」
- 「继续练习」按钮 → 直接进入该科目的练习模式

### 4.2 练习模式（章节练习，即时反馈）

- 进入后按 `chapter` 字段把题目分组，默认从第一章开始
- 顶部有个「第 X 章」的胶囊按钮，点击弹出章节切换列表
- **答题后立刻显示对错**（选中选项变绿/变红，其余变灰），有解析就在下面展示解析卡片
- 答完一章后有个小结页：可以「重新练习本章」「切换章节」「返回首页」

### 4.3 学习总览的 6 个数字怎么算的（这点很重要，之前踩过坑）

之前有一版这几个数字是写死的占位符，后来全部改成了真实计算：

| 显示项 | 计算方式 |
|---|---|
| 已练习题数 | 所有科目 `paperStats.done` 之和 |
| 平均正确率 | 所有科目 `paperStats.correct` 之和 ÷ 已练习题数 |
| 连续打卡天数 | 从今天往前数，`activityDates` 里连续有记录的天数，中断就停 |
| 模考次数 | `examHistory` 的记录条数 |
| 模考通过 | `examHistory` 里 `passed=true` 的条数 |
| 当前错题 | `wrongBook` 的记录条数 |

**「已练习题数」的统计口径：练习模式答的题 + 模拟考试答的题 + 错题本测验答的题，全部算，不区分来源。**

### 4.4 模拟考试

- 开考前的规则页显示时长/题数/合格线（第 3.2 节的表）
- 答题时**不显示对错**（这是跟练习模式最大的区别），可以用「题号导航」随时跳到任意一题改答案
- 右上角倒计时，最后 5 分钟变红提醒；时间到自动交卷
- 「交卷」按钮随时可点，交卷前弹窗二次确认：
  - 还有题没答完 → 「检测到未完成所有题目做答，请问是否确认提交？」
  - 全答完了 → 「请确认是否提交。」
  - 按钮是「是」/「否」
- 交卷后：算分、判断是否达到合格线（≥70%）、写入 `examHistory`、把答错的题写入 `wrongBook`
- 出分页可以「逐题复盘」（对/错分别标绿/标红，有解析显示解析），也可以「重新测试」或「返回题库列表」

### 4.5 错题本

- 首页只显示「科目 + 错题数」的卡片列表，**不要一上来就把所有错题铺出来**（体验会很糟）
- 点进某个科目才展示该科目的错题，每条可以展开查看完整题目/选项/解析
- 「组一次错题测验」：默认全选当前科目的所有错题，可以取消/勾选，「全选/取消全选」按钮放在页面右上角（不是底部，之前调整过）
- 测验时的反馈方式跟练习模式一样（即时反馈），**答对的题会立刻从错题本删除**

### 4.6 「我的」页面的模拟考试记录

- 默认只预览最近 3 次
- 超过 3 次会出现「查看历史记录（近 X 次）」按钮，X 最多 20
- 点击进入独立列表页（最多显示 20 条），点某一条可以查看那次考试的出分详情和复盘

## 5. 需要特别注意的实现细节

### 5.1 头像和昵称——不能用 `wx.getUserProfile`

微信官方已经禁止小程序「一键获取」用户头像昵称，正确做法：

```html
<button open-type="chooseAvatar" bindchooseavatar="onChooseAvatar">选择头像</button>
<input type="nickname" bindblur="onNicknameBlur" placeholder="请输入昵称"/>
```

原型里用「点选 8 个预设图案 + 文本框填昵称」模拟的就是这个交互，实际开发换成上面这两个真实组件即可，交互流程保持一致：选头像 → 填/确认昵称 → 点「完成」进入首页。

「我的」页面右上角的编辑图标，点击后应该跳转到同一个「选头像+填昵称」的界面（只是标题换成「编辑资料」，并加一个返回箭头，保存后回到「我的」页面而不是强制跳首页）。

### 5.2 登录态判断

未登录时不能看到任何 Tab 内容，只能看到登录页（以及登录页链接出去的用户协议/隐私政策页面）。已登录但还没填过资料（首次登录）时，要先过「完善资料」这一步才能进首页。

### 5.3 章节切换 / 题号导航 / 全选按钮的样式规范见「6. 设计规范」，这里只强调交互层面：

- 练习模式的章节切换、模拟考试的题号导航，都是「点击胶囊按钮 → 从底部弹出面板 → 选完自动收起」的模式，不要做成跳转新页面
- 模拟考试的题号导航面板里，已作答的题号是实心绿色，当前题有一个绿色描边+浅色光晕（不要用生硬的细线描边，之前这版设计被反馈过"像一条丑的黑线"，改成了描边+柔光的组合）

### 5.4 「答对自动移除错题」这条规则要在 3 个地方都实现

1. 练习模式答对 → 检查错题本里有没有这题（按 `paperKey + stem` 匹配）→ 有就删
2. 模拟考试交卷时，逐题检查 → 同上
3. 错题本自己的测验答对 → 同上

反过来，答错了要写入/更新错题本（如果已存在则更新 `lastPicked` 和 `wrongAt`，不要重复插入）。

### 5.5 模拟考试的题干显示要去掉原始编号

题库里的 `stem` 字段开头都有「N. 」这种编号（章节内顺序），但模拟考试是跨章节随机抽题，显示原编号会造成误导（用户会以为题目顺序不对）。**渲染模拟考试题目和错题本测验题目时，要先用正则 `stem.replace(/^\d+\.\s*/, '')` 去掉这个前缀**，只在练习模式里保留原编号。

## 9. 原型里「故意」没做成真的的地方（开发时需要补齐）

- 所有用户数据（学习记录/错题本/模考历史/头像昵称）目前都是浏览器内存变量，刷新即清空——真实开发必须接数据库
- 微信登录、头像选择器都是模拟的交互效果，需要换成真实的微信 API（见 5.1、5.2）
